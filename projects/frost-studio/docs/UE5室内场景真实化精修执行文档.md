# 霜境 · UE5 室内场景真实化精修执行文档

版本：2026-09-28 / 第一版。适用项目：blue-white-room / FrostRoom，UE 5.7。

本文件是待执行的制作规范，不是精修完成报告。依据为用户最新六张图片、当前源代码和已有导出报告；本次未进行新的 UE 运行验收。第一张是美术目标，第二至第六张是当前场景问题截图。目标图用于指导形状、色彩、表面和光照，不用于证明真实产品尺寸、隐藏结构或角色接触正确。

保留现代高层景观房、睡眠区、客厅和窗边工作区的布局；保留角色的二次元外观。角色原文件不改，制作副本修正。UE 开启时在同一实例内迭代，不自动关闭、重启或重复启动。现有配置、选择、拆装、保存恢复及兼容性功能均为回归保护项。

## 第一部分：项目现状诊断

### 1. 完成度与证据边界

当前属于“基础场景已经搭建、进入精修前阶段”。已有房间布局、设备结构、角色导入和部分 PBR 贴图，但还没有达到近距离观察可信的成品状态。不能以成功启用 Lumen、增加模型数量或材质名称多样，代替画面验收。

代码确认：

- `src/scene/models.ts` 的鼠标主体和耳罩仍由倒角方块构成；键盘主要采用同尺寸键帽，仅空格键做明显宽度变化。
- `src/scene/soft.ts` 的床枕、沙发和椅子软包共用球体变形方法，主要差别为尺寸和种子。被褥褶皱依赖正弦函数，缺少明确的拉力、压缩和悬垂位置。
- `src/scene/surfaces.ts` 已加载布料法线、粗糙度和 AO，所以不能诊断为“完全没有贴图”；需要检查导出后是否保留连接、尺寸和强度。当前 `metricUV` 按顶点法线主轴选择投影，曲面上有方向突变风险，应由近景检查确认。
- 同文件玻璃为 `transmission:0`、低 opacity 的近似。它不等同于有厚度、透射和正确反射的玻璃。
- `room_sample.py` 通过统一缩放、偏移和导入坐姿放置角色，没有实现手脚 IK 和布料碰撞修正；`character_sample.py` 对各材质槽统一使用较高粗糙度，皮肤、布料和金属饰品差别不足。
- 已有 cinematic 报告记录软件 Lumen 和关闭硬件光追；报告中的截图完成不代表人物接触、性能或画质达标，也不代表目前正在运行这一关卡。

### 2. 最影响真实感的十项问题

| 顺序 | 问题与画面依据 | 判断与修复方向 |
|---|---|---|
| 1 | 人物袖摆、饰品与扶手、椅脚交叠，脚部支撑不清楚（图2、6） | 高风险接触问题；须在侧面、背面与鞋底视角确认，不能仅凭单图确定穿透深度 |
| 2 | 白色设备与家具相互混同（图2—4） | 材质、曝光和形状共同造成；固定曝光后分别检查 Base Color、Roughness、Normal |
| 3 | 沙发靠背、坐垫和枕头像重复的圆润块体（图6） | 缺少承重变形、张力差异和结构性接缝 |
| 4 | 被子呈重复波纹，枕头与床垫边缘生硬（图6） | 需要按重力、接触与叠层重做形状，而非叠加噪声 |
| 5 | 鼠标、耳罩、键帽缺少工业产品曲面（图3） | 轮廓必须回模型层修正 |
| 6 | 机箱内部白灰色混成一体，软管和线材粗硬（图4） | 分离 PCB、散热器、接头、编织线和玻璃，核对连接与半径 |
| 7 | 茶几表面像拼贴地砖（图5） | 检查所用图集、UV 和贴图内容，选择整块石材或木饰面逻辑 |
| 8 | 屏幕与窗外使用相似强烈景观，抢占视觉重心（图3） | 调整屏幕亮度、内容和窗外尺度，不能靠压暗整个房间补偿 |
| 9 | 叶片疏密与方向机械，杯子和书缺少结构（图5） | 模型结构不足；在主要接触修好后精修 |
| 10 | 大面积亮白表面缺少稳定的局部明暗与接触感 | 先确认几何贴合及阴影，再调整定向自然光和补光 |

### 3. 必须先修与后续加分项

必须先修：人物接触、手脚可见性、明显悬浮或相交、主机连接逻辑、软装轮廓、材质错误绑定和过曝。后续加分：小面积使用痕迹、标签、书脊、布边线头、屏幕内容变化和细微灯光呼吸。细节不能掩盖前一类错误。

## 第二部分：精修优先级规划

### P0：几何、接触及诊断基线

1. 保存独立精修关卡、源资产副本、导入映射和同机位截图，锁定家具根坐标。
2. 固定诊断曝光，排查丢贴图、法线方向、材质槽和透明面遮挡。
3. 修正骨盆落座、手指与大腿或扶手、鞋底支撑及袖摆绕行；静态姿态通过后才加入动态。
4. 消除沙发垫、床品及桌面设备的大块穿插，修正主机线管的起终点。
5. 拍摄正面、侧面、背面和手脚特写，建立每个问题的关闭证据。

### P1：决定近景可信度的主体制作

1. 沙发、被褥、枕头分开建模，增加自然受力形状和接缝。
2. 电竞椅重做包覆结构、弧面扶手、调节机构、五星脚与双滚轮。
3. 鼠标曲面、耳罩环形软垫、键帽凹面及显示器背壳精修。
4. 建立织物、皮革、喷涂金属、裸金属、塑料、石材、PCB 与玻璃独立材质实例。
5. 调整窗光方向、局部反射和接触阴影，完成白天与夜间的受控对照。

### P2：完成度与效率

1. 添加克制的磨损、指纹、布边和小道具；新品不做过度锈蚀或脏污。
2. 修饰植物与柜内陈设，丰富远、中景而不遮挡工作区。
3. 动态接触复测、LOD、材质合批、透明层控制和性能分档。
4. 制作真实运行录屏及固定机位对比，逐项关闭验收任务。

## 第三部分：分模块执行方案

### 模块A：整体空间与构图

**问题 → 原因：** 高位广角容易掩盖接触错误，也会把床、椅子及桌面比例拉开。单张目标图不足以确定隐藏区域尺寸。

**具体方案：** 保持 `layout.ts` 与共享配置的家具根位置；相机独立移动。入口采用站立人眼高度，另设桌搭、手、脚、沙发和床品诊断机位。复核桌下腿部空间、椅背转动范围及通道，隐藏尺寸标记“推定”。

**UE 落地：** 保存命名 CameraActor 或 CineCameraActor，固定输出比例、FOV 或传感器与焦距组合；不把毫米焦距直接填入 FOV。将家具根变换输出为 JSON，修改后比较；需要修正接触的子网格或骨骼单独记录，不以“不变布局”为由拒绝必要姿态调整。

### 模块B：人物模型与穿模修复

**问题 → 原因：** 截图中袖摆与扶手、饰物与椅脚关系不清。现有坐姿并非针对当前椅子逐点约束，整体偏移不能同时解决骨盆、手、脚。

**具体方案：** 保留角色原比例，先测座垫受力面、骨盆、左右膝踝、掌心与鞋底。先骨盆，再腿和脚，再肩肘腕与手指，最后整理袖口、裙摆和发束。穿模修复使用局部姿态、权重或修正形态，不压扁人物或缩短四肢。高跟鞋按鞋跟和前掌接触地面，不要求整块鞋底贴平。若自然姿态无法落地，采用尺寸合理的脚踏，并明确作为新增家具。

**UE 落地：** 在原 Skeletal Mesh 副本上建立骨骼映射；使用 Control Rig 或修正 Pose 驱动四肢，再以动画曲线平滑混合。Physics Asset 调整碰撞体，而非将碰撞体误当作渲染网格；它本身不会自动修好静态姿态。衣摆先用骨骼或修正形态避让；确有收益时再建立 Chaos Cloth，并验证碰撞传入与约束权重。[Physics Asset 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-asset-editor-in-unreal-engine?application_version=5.7)、[Panel Cloth 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/panel-cloth-editor-overview?application_version=5.7)。

**接触验证：** 手、脚各拍近景与侧面，确认指缝、腕部、鞋跟清楚；用线框与剖视查几何交叉，再关闭调试检查阴影。动画采样只作初筛，连续运行至少两分钟并环绕观察；骨盆不漂移，手掌不滑穿，衣饰不反复穿出扶手。记录穿模部位、时间点、相机和修复方式，不能用单张正面截图宣称全部消除。

### 模块C：电脑椅精修

**问题 → 原因：** 椅背软包块体重复，侧翼与人物衣饰争用空间，材质细节与结构不一致。

**具体方案：** 重做有腰部收分的背壳、分片软包、座垫前缘和受力压痕；扶手使用软质顶面、硬质外壳、金属升降杆三层结构。五星脚有截面变化和轮架，轮子有双轮及轴，不以粗圆管代替全部结构。缝线沿真实分片边界走，不穿过人物。

**UE 落地：** 椅壳、软包、扶手、气杆、底座拆成少量语义明确的网格；皮革与塑料分别设材质实例。椅子碰撞使用简化形体，接触区域重点拟合。调节座高后必须重新核对人物，而不是只拍空椅子。

### 模块D：桌面工作区精修

**问题 → 原因：** 鼠标方硬，耳罩像方盒；均匀键帽与支架缺少产品结构。

**具体方案：** 鼠标重建拱背、前低后高、左右键分缝与独立滚轮。耳机使用椭圆壳、内凹耳垫、织物防尘网、转轴和头梁压垫。键盘按布局区分 Tab、Shift、Enter 等宽度，加入键帽顶面浅凹与行高变化；灯光从字透和键缝出现，不能整块发白。显示器增加背壳曲面、接口凹槽、支架转轴和底座胶垫。笔记本保留独立屏幕身份。

**UE 落地：** 重点曲面在建模源文件制作，低成本重复件实例化；字透使用裁切贴图和独立发光遮罩。近景检验键帽法线，避免过度圆滑丢失轮廓。桌面保留板厚、封边和抽屉门缝，线材沿后缘进入理线槽。

### 模块E：机箱与内部硬件精修

**问题 → 原因：** 内部零件虽多，但重复鳍片、白色硬管和近似材质使结构像示意模型。

**具体方案：** 按框架、玻璃、主板托盘、PCB、散热片、风扇、冷排、冷头、线缆和接口分层。玻璃具有可见边缘；金属开孔、固定柱与螺丝对应安装位置。风扇有独立叶片、轮毂和框架；冷排与风扇相接而不相穿。软管使用合理曲率，端部接头有套环。主板供电、显卡供电和水冷管分别有可追踪起终点；理线梳不穿入插头，导线不悬空终止。

**UE 落地：** 以命名零件建立材质槽与拆装 ID，保留现有选择关系。PCB 用绝缘基底、焊盘金属与少量凸起元件分层，不能整块金属化。细小鳍片优先合并或烘焙到近景资产，避免无收益地增加 Actor。SKU 结构未核实时标记参数化示意，不编造型号标识。

### 模块F：沙发与茶几精修

**问题 → 原因：** 沙发用同一类鼓包形状缩放，无法体现坐垫承重与靠背张力差异；茶几图案像地砖。

**具体方案：** 坐垫形成浅压陷和向边缘扩散的褶皱；靠背有重力下垂，扶手轮廓更紧实。左右抱枕用不同压缩、旋转和接触形状。按缝制方向展开 UV，不能靠主轴投影处理所有软曲面。茶几选完整石板逻辑，顶面与侧面纹理匹配，保留小倒角和底座接触。杯子增加杯口壁厚、内腔和把手，书增加封面、书脊和页块。

**UE 落地：** 分别制作坐垫、靠背与抱枕资产，使用共享织物母材质加颜色实例。与座框交界保留合理缝隙；石材更换为适合整板的图集，先检查法线和 UV 再调粗糙度。不要用强 AO 把所有边缝涂黑。

### 模块G：床与寝具精修

**问题 → 原因：** 被子周期波纹缺乏重力方向；枕头鼓起和被褥悬垂未与床垫接触统一。

**具体方案：** 床架、包覆床头、床垫、床单、被子和床尾毯分层。床垫有侧围与包边；枕头四角略收紧，中部饱满但不完全对称。被子主要褶皱从压点和床边过渡，越过边缘后向下垂落，有厚度，避免浮在床垫上。床尾毯褶皱应受下层被子影响。

**UE 落地：** 静态寝具优先在建模副本里模拟或雕刻后冻结，烘焙细褶；不必实时模拟整床。较大轮廓靠网格，小褶靠法线，纤维靠细节法线。贴图密度统一并检查包边与床框相交。

### 模块H：柜体、电视墙、植物与装饰

**问题 → 原因：** 柜格物品、花盆和杯书仍是基础几何，叶片分布重复。

**具体方案：** 柜门明确门缝、拉手和底座，层板有厚度；灯条藏在槽内，增加扩散罩。道具选择少量有轮廓的书、盒与杯，不堆满展示格。植物保留分枝、叶柄、薄叶、叶脉和新老叶色差；花盆有盆沿、土壤和内壁。

**UE 落地：** 叶片材质与枝干分离；使用透明裁切资源时检查轮廓、Mipmap、双面阴影与过度绘制。避免为了复杂度改成昂贵 Groom；角色头发先保留原有发片与辨识度。

### 模块I：地板、墙面、窗体与环境

**问题 → 原因：** 窗外过近、太鲜艳和无室内反射会形成壁纸感；平面投影可能导致木纹方向和比例不一致。

**具体方案：** 地板按板宽与铺装方向调整 UV，减少明显重复。墙面轻微涂层纹理，不出现砂石级凹凸。窗框区分型材、压条、密封胶与玻璃。远景保持远山尺度，中景可以增加实际地形层；二维全景只能作为远景，不声称具有近景视差。

**UE 落地：** 室外背景和照明环境分别管理但方向与色温协调；玻璃单独网格与材质，验证反射、透射、排序和 Nanite 设置。避免给每扇窗重复一张完整风景。玻璃前后分别截图，排除“完全无玻璃”与“黑色镜面”两种错误。

### 模块J：材质系统整体升级

建立少量母材质与实例，按材质语义绑定，避免依赖导入时不断变化的编号。下面数值为诊断起点，不是品牌产品测量值；在固定曝光、同一光照下比较。

| 表面 | 初始 Roughness 区间 | 关键分层 |
|---|---|---|
| 乳胶漆 | 0.75—0.95 | 低幅度微法线，非金属 |
| 织物 | 0.75—0.95 | 织纹、纤维高光、宏观褶皱分频 |
| 皮革软包 | 0.45—0.7 | 皮纹、压痕、缝线；不复用硬塑料反射 |
| 喷涂白色外壳 | 0.35—0.6 | 涂层为非金属，裸露金属另用遮罩 |
| 裸露拉丝金属 | 0.2—0.45 | 金属度接近1，拉丝方向跟随零件 |
| ABS / PBT | 0.45—0.8 | 微颗粒与局部光滑磨损，金属度0 |
| 木饰面 | 0.4—0.65 | 木纹方向、板缝与清漆层 |
| 石材 | 0.25—0.55 | 矿物纹路与抛光程度，不能泛用地砖图案 |
| 玻璃 | 0.02—0.12 | 透射与反射、边缘厚度，金属度0 |

通道规范：

- **Base Color：** 颜色贴图使用 sRGB。白色在固定曝光下保留明暗余量，不统一改纯白或统一改灰。不要把定向阴影烘进所有基础颜色。
- **Roughness：** 非颜色数据。区分大面积反射与轻微使用变化，避免整片同值或过强噪声。
- **Normal / Detail Normal：** 非颜色数据；确认 UE 的 DirectX 法线方向，Web 原有 OpenGL 法线不能无检查复用。通过方向测试决定是否翻绿通道，禁止重复翻转。微法线表达细纹，不改变物体轮廓。
- **AO：** 非颜色数据，采用正确 UV；只补局部遮蔽，不能当作解决穿模或漂浮的黑边。
- **Height / Bump：** 用于适量凹凸或烘焙法线；明显轮廓、杯口、键帽曲面、被子厚度回到几何处理。不对所有材料启用高成本位移。
- **Edge wear：** 接触频繁的边缘少量使用，白漆掉落时才露出金属；新品不做统一银边。
- **Dirt mask：** 接缝、轮子和接触区克制增加，不污染脸部和所有白面。
- **Curvature / cavity：** 由实际网格烘焙或制作遮罩辅助边缘与凹槽分层；项目尚无相应贴图时标记待制作，不能声称资源已存在。

近景重点资产优先 1K—2K，远景更低；只有清晰度检查确实需要时才升 4K。每项下载记录来源、作者、许可、修改及署名；继续保留现有 `public/materials/*-license.json`。

### 模块K：灯光与后期

**问题 → 原因：** 亮度可以掩盖纹理，也可能暴露缺少曲面和接触；加环境光不会修复这些源头问题。

**具体方案：** 窗光为主方向，室内补光只恢复暗部。主光、窗框阴影与景观太阳方向一致；日景先固定曝光做材质诊断，再制作夜景。夜景以温暖室内灯和偏冷外景区分，蓝色灯带只是点缀。屏幕发光受控，手部与白衣保留结构，脸部不强行真人化。

**UE 落地：** 沿用可运行的软件 Lumen 基线，检查 Surface Cache 与 Mesh Distance Fields，墙、地面和天花分开。角色不应假定获得与静态家具完全相同的离屏追踪效果；相机切换时单独检查阴影与反射稳定性。官方说明软件距离场的几何覆盖及硬件光追的蒙皮支持有所不同；不得把开启 Lumen 等同于所有角色反射都正确。[UE 5.7 Lumen 技术细节](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine?application_version=5.7)。

Post Process Volume 使用受控曝光和中性色彩起点；先关 Bloom 检查材质，再小幅恢复发光溢出。锐化不补缺失细节，景深不遮穿模。接触阴影先修物体距离、阴影精度与偏移，再考虑短距离补充，不叠出一圈黑边。需要引擎重启的渲染设置暂列待办，遵守用户不反复重启 UE 的要求。

### 2. 系统检查边界

| 系统 | 本项目检查重点 |
|---|---|
| Nanite | 按资产评估；玻璃、透明片与角色不能照搬不透明静态家具设置；检查警告和 fallback |
| Lumen | 查看缓存和距离场是否覆盖主体，不仅看项目设置开关 |
| Virtual Shadow Maps | 确认实际启用状态；检查细节阴影与成本，不用高偏移解决所有瑕疵 |
| Post Process Volume | 曝光来源统一，排除 Camera 与 Volume 覆盖冲突 |
| Material Instance | 按语义命名，保存源材质；同类复用，不同材质不混槽 |
| Groom / Hair Card | 优先修现有发片边缘、透明裁切与骨骼跟随；不强制上 Groom |
| Skeletal Mesh | 检查比例、骨骼、权重、LOD 与表情导入，不能把静态姿势算自然动画 |
| Physics Asset / Collision | 分清物理形体、查询碰撞和渲染表面；逐个验证用途 |
| Cloth | 静态接触优先；只对确有需求的布片启用，验证碰撞、约束与重置稳定性 |

### 3. 不能靠后期修复的事项

手脚穿模、衣摆穿椅、鼠标方盒轮廓、耳罩无内腔、杯子无杯口、床品漂浮、线材没有接口、沙发压陷方向错误、UV 拉伸和玻璃厚度错误都应回模型、绑定或材质源头处理。加 Bloom、提高锐化或遮挡问题部位不构成修复。

### 4. 性能与保存策略

低、中、高档分别记录渲染比例、阴影、反射、贴图与透明效果差异，不能只换名称。固定输出 1600×900、相同机位与动作，预热后采集至少两分钟的 Game、Render、GPU 帧时间及内存，报告中位数和慢帧分位数；首次加载单独记录。目标档位应实测后决定，不写死 FPS。

高质量静帧可另设离线渲染档，但不能用离线帧率冒充实时表现。修改前保存副本；导入优先新增版本并切换引用，通过后再整理。持续保留当前配置数据与模型 ID，禁止用新静态场景取代既有交互。

## 第六部分：最终验收标准

### 1）人物检查

- [ ] 正面、侧面、背面均使用提供的真实三维模型；角色辨识度与原服装保留。
- [ ] 骨盆、双手、双脚接触合理；近景能分辨指缝、腕部、鞋跟及脚部方向。
- [ ] 袖口、裙摆、饰品和头发不明显穿入身体、椅背、扶手、桌板或轮架。
- [ ] 连续动画至少两分钟不漂移、不跳变；暂停保留姿态，恢复平滑。
- [ ] 看屏幕、看窗外使用实际目标；没有完成的眨眼或衣物动态不标完成。

### 2）家具检查

- [ ] 沙发坐垫与靠背形变不同，抱枕受力可信，缝线与 UV 沿结构分布。
- [ ] 床品有真实叠层、厚度和悬垂，床垫、床架及床头关系正确。
- [ ] 柜门有门缝与拉手；茶几可辨石材或木材，不能像放大的地砖贴图。
- [ ] 椅子有可解释的支撑、调节和滚轮结构，人物坐入后仍无明显交叉。

### 3）电脑区检查

- [ ] 两台独立显示器屏幕朝向椅子，笔记本独立；支架与底座不悬浮。
- [ ] 键帽有布局差别与受控灯光，鼠标、耳机具备可信轮廓和分件。
- [ ] 主机装配层级明确，风扇、冷排、管路、电源和线材能追踪连接。
- [ ] 选择、颜色、拆装和恢复仍对应原对象，不因资产替换而失效。

### 4）材质检查

- [ ] 白色漆面、布料、皮革和塑料在同一机位中可以区分。
- [ ] 粗糙度与微法线尺度合适，无明显重复、接缝断裂、拉伸或反向凹凸。
- [ ] 金属高光、木纹方向、石材连续性和玻璃反射透射合理。
- [ ] 资源来源、作者、许可及必要署名完整，未制作的贴图不虚报。

### 5）光照检查

- [ ] 白色表面不过曝，暗部保留细节；窗外不过度抢眼。
- [ ] 阴影方向一致，人物与椅子、家具与地板接触稳定。
- [ ] 日夜色温和亮度有区别，蓝光不覆盖全室；Bloom 和锐化克制。
- [ ] 环绕时反射、阴影和曝光没有严重跳变、漏光或噪点。

### 6）整体完成度检查

- [ ] 提交入口、桌搭、人物手脚、主机、沙发茶几、床品与日夜对照；前后比较保持机位及画布一致。
- [ ] 所有视角共用布局，相机切换不重摆人物或家具。
- [ ] 实际运行录屏包含动态、环绕与材质近景；生成图仅作参考，不能代替验收。
- [ ] 构建及相关功能测试通过；记录画质档位、设备和实测帧时间，不报告未经测量的 FPS。
- [ ] 所有 P0 关闭后再评估成品等级；仍有明显穿模、占位轮廓或材质错误时，不称“专业级完成”或“照片级”。
