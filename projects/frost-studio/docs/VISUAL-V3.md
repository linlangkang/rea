# 房间视觉升级验收 · 2026-09-24

本次以已有可交互工程为基础，修改场景和资源系统。参考目标是用户提供的两张住宅电竞房间效果图；修改前截图来自实际运行页面，二者没有混用。隐藏的入口墙、门、尺寸和通道为推定，默认房间 8×8×3 米，不是从单张图测量得到的精确户型。

## 实际检查与成因

|原问题|检查结果和改动|
|---|---|
|家具像几何积木|原床品、沙发主要使用倒角盒。现在床垫包边、鼓起与凹陷的枕头、独立座垫/靠背/扶手、褶皱被子和带 3mm 边缘的毛毯分开建模；仍属参数化模型。|
|叶片厚重重复|原叶片是反复缩放的实体几何。现在使用细枝干和无实体厚度的弯曲叶面，改变叶片尺寸、角度与分布。移除入口左前方植物，右侧植物缩小并后移。|
|材料没有区别|原大部分物体共用颜色加粗糙度参数。现在区分乳胶漆、扫描木纹、织物、地毯、石材、喷漆、金属、拉丝金属、塑料、电路板、玻璃、屏幕。|
|窗外黑色|本次修改前实测山景 HTTP 200，截图可见，未复现用户曾见的全黑。旧实现缺少失败提示和有色占位，两个窗面重复映射照片。新实现为连续远景；等待或失败时保留蓝灰天空和可操作界面，资源状态记录请求/解码结果，支持重试。不能据此断言历史黑屏只有一种原因。|
|床头方向错误|原床旋转导致床头横在窗前。现在床旋转 π，床头靠 +Z 入口实体墙，床尾向室内。|
|极端广角|旧默认相机在约 2.05m 高度、垂直 FOV 72°。新入口高度 1.65m，按画布比例从水平视角计算垂直 FOV，并限制为 35–58°。|
|灯光平、缺乏接触|增加窗外定向主光、天空/地面半球补光、上行反弹近似、暖色面光和家具底部接触阴影近似。方向随时间变化；未使用全屏 Bloom 掩盖问题。|
|界面遮挡|移除画面中的大标题和长操作提示，保留小型状态与全屏按钮。操作说明移到场景设置。|

## 布局与功能

`src/scene/layout.ts` 是默认布局与相机数据的唯一入口。单位米、Y 向上，入口在 +Z，左侧与后方玻璃分别在 -X / -Z，电视在 +X。家具在切换镜头时不改位置或旋转。尺寸编辑仍保留；扩大房间不会偷偷移动家具，因此自定义尺寸需要自行核对靠墙关系。

- 床头在入口实体墙旁；默认镜头看向床尾，床品镜头用于检查床头。
- 两个独立显示器背向左窗、屏幕朝椅子；笔记本独立放在桌面前端，主机在另一端。
- 中央沙发面向 +X 电视，茶几位于两者之间；冰箱、零食柜位于右墙区域。
- 门增加门套、门缝、把手、铰链；柜体增加厚度、分缝、拉手、底座；显示器保留后壳、支柱、底座；机箱保留独立结构、玻璃和螺丝。
- 旧方案迁移会保留 SKU 与颜色，应用修正布局；不会自动覆盖原本地存档，用户点击保存才写入。
- 默认关闭坐标轴、包围盒和线框；全屏使用浏览器 Fullscreen API。
- 电脑与电视使用独立的写实风格山海画面。两张图片为本项目生成素材，不是实地摄影或动漫图。

## 环境、时间与光影边界

高山流水、海岸为单张图片的连续 180°远景曲面；云山为 HDR 球形远景。没有逐窗重复照片。山海背景有视角投影近似，不能提供真实近景视差；鸟瞰剖视能看到远景边界，不代表实际建筑悬浮在山谷里。

HDR 环境照明与可见背景分别管理。时间滑杆控制自然光高度、方向、暖冷及日夜状态；夜间采用偏冷月光近似和暖室内灯。未模拟真实经纬度、日期、月相、天体轨道或太阳/月亮实体。夜景沿用调暗后的日景素材，因此不是实拍夜间天空。

色彩管理为 sRGB 输出 + ACES Filmic；仅一盏主光生成阴影。没有实时全局光照或光线追踪；面光不生成真实面积软阴影，家具底部是解析接触阴影近似，不能称为烘焙 GI。窗玻璃使用低不透明度与环境反射的近似，避免多次透射导致黑窗和性能下降；未启用真实折射、厚玻璃焦散或屏幕空间反射。

**没有接入 DLSS 5。** 本工程运行 Three.js WebGL。NVIDIA 的 [DLSS 5 官方研究说明](https://research.nvidia.com/labs/adlr/DLSS5/) 描述了依赖渲染输入和运动信息的神经渲染体系；当前工程没有相应原生渲染集成，不提供虚假的 DLSS 开关。机器检测到 RTX 2060 / Intel UHD，但具体浏览器实际渲染器以测试记录 `gpu` 字段为准。

## 画质与性能

|档位|像素比上限|阴影|各向异性|
|---|---:|---|---:|
|低|1|关闭动态主光阴影，保留接触阴影近似|2|
|中|1.4|1024 阴影贴图|4|
|高|2|2048 阴影贴图|8|

上限还受设备 DPR 和 GPU 能力限制。DPR=1 的测试设备切换高档不会自动超采样至 DPR=2，因此三档 FPS 不保证严格递减。使用共享材质/几何体，软家具降低网格密度；未给所有物体配 4K 贴图。FPS 由真实动画帧数量与实际时间窗口计算，不是固定数字。

最新稳定采样见 `../output/visual-v3/verification.json`：每档等待 4 秒再记录 3 个 1.6 秒间隔样本；页面 1600×1000、画布 1600×740，Chrome 无头模式。浏览器渲染器、三角面、Draw Call、资源状态与相机坐标一起记录。读数是当前机器和视角的测量，不是游戏性能承诺。

本轮实际浏览器使用 **Intel UHD / ANGLE D3D11**，不是 RTX 2060。云山入口固定机位的三次样本：低档 30 / 32 / 30 FPS，中档 30 / 30 / 31 FPS，高档 28 / 28 / 29 FPS。近景/鸟瞰帧率因可见模型数量不同而变化。虽然机器有独显，本次没有修改用户的系统 GPU 偏好。
