# 2026-10-21 场景材质与运行效率优化

本轮修改独立项目 `blue-white-room` 的 Vue / Three.js 网页场景。本机预览地址为 http://127.0.0.1:5179/ 。没有关闭、重启或修改正在运行的 UE 编辑器；本次网页验收结果不能代替 UE 编辑器中的验收。

## 实际变更

- 将演示沙发改为 2.8 米长的三人款，分别建立底座、扶手、三个坐垫、背垫、抱枕与披毯；补织物颜色细节、法线、缝边和边缘明暗。它仍是参数化示意，尺寸不代表某个品牌的官方产品。对旧存档中名称、尺寸和模型均未修改的原默认 2.2 米沙发，在内存里更新为新款；自定义家具、原始存档、实例位置与配色保留，点击保存后才写入。同步修正公开目录 JSON，避免导入时恢复旧尺寸。
- 床品、地毯和窗帘共用有尺度的织物贴图，独立设置双面布料材质。修正地毯收边曲线超出轮廓的问题，调整披毯的接触位置。织物颜色纹理是本项目生成的纱线示意，法线和粗糙度沿用现有授权资源。
- 皮革使用现有 Leather White 颗粒法线；只将明确标注 DirectX 的法线绿色通道翻转一次。桌面漆层、裸露金属、涂装金属、塑料、PBT 键帽、橡胶和皮革分别设置反射特性。
- 缩小桌面、桌腿和笔记本等物件的倒角，补笔记本铰链与接口。保留主机中的散热鳍片、插槽、螺丝、理线、风扇叶片以及键盘键帽等可见结构。
- 机箱玻璃不再投下不透明整板阴影。窗光、阳光、室内补光、屏幕补光与 LED 分开控制，降低白天的蓝色泛光。使用 AgX 色调映射和 2048 阴影图，控制高光和阴影边缘。
- 植物的每组 43 片叶子改为实例绘制，保留细薄曲面、不同朝向和枝干结构；适度减少柔软模型上不可见的冗余面数。

## 帧率与资源处理

静态网格按材质、空间区域及选择归属合并。两块内存、两台显示器、可拆部件、冰箱门、风扇与透明物件保留独立边界，保证拾取、拆装和开门继续工作。最终场景从 1189 个网格降到 704 个，合并减少 485 个网格（包含按需显示的远景代理）。

主机内部另设远景结构：相机距离超过 4.2 米时使用少量结构轮廓，进入 3.6 米内恢复完整模型，两个距离之间保持当前级别以避免闪烁。高画质、部件选中、拆装和调试模式强制完整细节。几何与尺寸数据保留；GLB 导出复制完整模型，不导出远景代理。当前优化不会把低细节版本作为原始资产保存。

静态布局的太阳阴影只在布局、光照、拆装或冰箱门变化时更新。流水使用 GPU 位移和解析法线，取消每次在 CPU 重算顶点及法线。屏幕在视锥外停止画布更新；可见的摄影桌面时钟约每秒更新一次，动态壁纸仍继续运行，减少动态偏好会停止非必要运动。

本轮保留原始素材，新增内容哈希命名的运行资源与映射表。颜色使用 WebP；AO 与粗糙度合并到同一张数据贴图，法线不进行二次有损编码：选择更小的无损 WebP，或者逐字节复制已有 OpenGL JPEG。HDR 在**线性辐亮度**空间平均，2K 原始文件保留，网页使用 512×256 版本，文件由 6,083,170 字节降到 408,632 字节。反射中的细小环境细节会相应减少。

`src/scene/render-assets.json` 管理运行路径，`public/licenses/runtime-assets.json` 记录尺寸、格式、字节数及来源清单。重新生成时，在项目根目录执行：

```powershell
# 需要本机 Python 和 Pillow；普通 npm 构建不要求安装 Pillow。
npm run assets:pack
```

Three.js 运行库单独打包，以便场景代码改变后继续使用已有浏览器缓存。GLB 导出器保持延迟加载。Nginx 模板增加文本压缩、带内容哈希资源的长缓存和 HTML 重新验证；这只是本地模板修改，尚未部署或用 Nginx 实例验证。

## 已完成的实测

Chrome 无头浏览器，Intel UHD Graphics / ANGLE Direct3D11，视口 1600×1000，画布 1080×843，像素比 1，中画质、白天、默认机位。均等待资源就绪和机位稳定后采样，每次间隔 1.6 秒。

| 指标 | 修改前 | 优化后短时采样 |
| --- | --- | --- |
| FPS | 20、21、22、21 | 25、26、25、25 |
| 每帧绘制调用 | 780 | 291 |
| 当前机位三角形 | 600,478 | 372,820 |

初期 23、27、24、24 的采样之后，复测曾下降至 16、12、15、12；没有将该低帧率结果隐藏，随后补充主机远景分级再测。原始中间数据保存在 `output/realism-2026-10-21/before-lod.json`，分级后的记录为 `after.json`。这些是本机短时观察，不是跨设备帧率保证，也没有达到稳定 60 FPS。

禁用本次测试页面缓存后，材质、环境和零食模型的实际传输量为 7,394,525 字节；此前相同分组为 21,653,826 字节，减少约 66%。该数值不包含网页代码，也不代表公网下载耗时。原始素材并未删除，部署目录总体磁盘占用与浏览器运行下载量不是同一指标。

运行状态检查：静止时阴影更新计数不变；开冰箱门会触发更新；门停止后计数再次保持稳定。默认机位摄影屏幕在 1.8 秒内仅更新两次。实际图像和原始基线见 `output/realism-2026-10-21/`。

验证结果：`npm test` 59 项通过（包含旧沙发更新与自定义数据保留），`npm run test:e2e` 21 项通过（最后完整回归 3.1 分钟），`npm run build` 通过。浏览器覆盖独立选择、拖动不误选、颜色/尺寸、十次拆装、灯光、上下文丢失恢复、存储、资源失败回退、移动端以及 UE 配置 JSON 导出。完整结果保存为 `output/realism-2026-10-21/full-browser-results.json`；房间、桌搭、主机和移动端截图位于 `output/playwright/`。构建仍有 Zod 第三方注释提示和 Three.js 包体积提示，没有将警告隐藏。

从远景模式实际导出了 `output/realism-2026-10-21/room-full-detail.glb`（68,258,920 字节），检查二进制头及场景 JSON：1816 个节点、511 个网格，包含 CPU、显卡、主板、内存、电源、SSD、水冷和风扇的完整部件，机箱节点仅一个，远景代理未混入导出，也未使用 `EXT_mesh_gpu_instancing`。检查结果为 `glb-check.json`。导出时 Three.js 提示了材质通道合并和法线归一化警告；没有导出错误。这里只完成了 GLB 结构检查，尚未在 UE 中导入验收。

查阅 [Three.js 官方网格优化说明](https://threejs.org/manual/pages/optimize-lots-of-objects.html)、[BatchedMesh 文档](https://threejs.org/docs/pages/BatchedMesh.html)、[Poly Haven 许可说明](https://docs.polyhaven.com/en/faq?q=commercial)、[ambientCG 许可说明](https://docs.ambientcg.com/license/) 与 [Fabric030 官方条目](https://ambientcg.com/a/Fabric030)。本轮静态合并使用 Three.js 的 BufferGeometryUtils，而非实例化 BatchedMesh。

Poly Haven API 返回 HTTP 403；ambientCG 的 Fabric030 元数据可读取，但其下载链接重定向后返回 403。已停止对受阻内容的自动请求。**本轮没有成功下载新的扫描材质包**，也没有绕过限制。实际使用的是项目原有、附带授权记录的素材和本地生成纹理。原始来源见 `docs/SOURCES.md`、`public/materials/*-license.json` 和 `public/models/long-life-food/source.json`。

窗外远景仍是生成的二维远景与少量近处三维几何组合；补光和接触阴影是实时近似，并非离线路径追踪或完整实时全局光照。现有参数化模型与所给电影级参考图仍有差距，不能将参考图或生成效果图当成运行截图。
