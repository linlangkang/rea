# 开发任务：蓝白电竞房间与电脑装机 3D 配置器

你是一名高级 Web 全栈工程师、Three.js 交互工程师和产品设计师。请开发一个可实际运行的前期测试版本，而不是只输出方案、宣传页面或静态效果图。

## 一、执行方式与授权边界

1. 先检查工作目录、AGENTS.md、README、package.json、锁文件、Git状态和已有实现。
2. 保留用户已有代码及未提交修改，不覆盖无关文件，不执行破坏性Git命令。
3. 新项目先初始化Git；已有项目沿用其结构和包管理器。
4. 开工前简要输出：需求理解、第一期边界、技术方案、页面结构、数据结构、预计修改文件。
5. 随后直接实施，不等待重复确认。只有缺失信息会实质改变方向或涉及新增权限时才询问。
6. 本次仅本地开发、运行和测试；未经明确授权，不发布网站、不购买资源、不调用付费服务。
7. 每个阶段保持项目可运行。遇到阻塞时说明原因、已尝试的方法和剩余影响，不用虚假成功状态掩盖问题。

## 二、产品目标与第一期范围

开发一个中文“3D电脑装机与电竞房间搭配工作台”。

第一期必须完成：

* 一间完整的蓝白电竞卧室。
* 一套指定默认电脑和双屏桌搭。
* 房间、桌搭、主机内部三个视角。
* 物体点击选中、信息查看、型号与颜色切换。
* 机箱侧板开关、拆解和组装动画。
* 灯光、屏幕亮度与日夜模式控制。
* 基础兼容性检查。
* 本地保存、恢复、重置。
* 测试产品目录、JSON导入和CSV模板。
* 实际测试记录、README及资源来源说明。

本期不开发账号、支付、购物车、云端数据库、自动全网爬虫、完整物理模拟或全品牌高精度数字孪生。

长期目标是覆盖近三年的各类产品，但不得将少量演示数据称为“全网全部型号”。

## 三、技术与架构

新项目优先使用：

* Vue 3、Vite、TypeScript。
* Pinia管理配置和场景状态。
* Three.js、OrbitControls。
* 原生CSS或Tailwind CSS。
* Vitest进行数据和兼容性测试。
* Playwright进行浏览器交互测试。

只有确实需要多页面时才引入Vue Router。

如果已有React或其他成熟框架，保留并说明原因，不为更换技术栈重建项目。

查阅官方文档，选择相互兼容的稳定依赖并提交锁文件，不盲目升级已有项目。

UI、产品目录、兼容性规则、场景渲染、动画、模型加载和存储逻辑必须分离，不能全部写进一个页面组件。

程序化模型为第一期允许方案。提供GLB/GLTF扩展入口；Draco、KTX2只在实际资源需要时配置，避免无意义加载解码器。

## 四、默认方案

### 台式电脑

* CPU：AMD Ryzen 7 9800X3D。
* 显卡：GeForce RTX 5070 Ti桌面版，不能替换成RTX 5070或笔记本版。
* 内存：64GB DDR5，32GB×2，场景中应显示两条内存。
* SSD：2TB NVMe。
* 主板：白色或银白色AM5 B850/X870，优先核验MSI MPG B850 EDGE TI WIFI或同级产品。
* 电源：白色全模组，850W起，最终功率和接口必须根据具体配置核验。
* 散热：白色360mm一体式水冷。
* 机箱：白色全景侧透机箱。
* 风扇：蓝白ARGB。
* 主板、内存、水冷、风扇和灯带：默认冰蓝色。
* 线材：白色编织线及蓝白灯效延长线。

实际兼容性必须基于具体板卡SKU，不能仅根据“RTX 5070 Ti”推断所有厂商版本的长度、厚度和供电接口。

### 桌面设备

* 两台27英寸显示器，均为2560×1440，横向并排。
* 高刷新率，具体数值以选定SKU核验结果为准。
* 白色或银白双屏支架。
* 蓝白键盘、鼠标、耳机和耳机架。
* 蓝白超大电竞桌、电竞椅。
* 主机位于桌面右侧或桌旁。
* 打开的白色笔记本位于桌面左侧。
* 扩展坞、插座、理线槽及DP/HDMI/USB-C线材。

双屏显示自制同步动态壁纸，电视使用自制画面，不使用未经授权的影视内容。

### 笔记本

目标名称为用户指定的“联想拯救者R9000P 2026冰魄白”。

实施时重新查阅联想官方产品页，核验正式名称、具体SKU、CPU、GPU、内存、SSD、屏幕、颜色和尺寸。

注意：

* “2026款”不自动等于实际发布日期为2026年。
* 同一系列不同配置分别记录，不拼接参数。
* 搜索摘要不足以证明全部规格。
* 无法核验时保留目标名称并标注“待核验”，参数留空；不要自行编造或悄悄替换。
* 第一版允许使用白色游戏本外观示意模型，并明确标注非官方精确模型。

## 五、房间布局与视觉

默认使用可调整的约8m×6m×3m房间，作为测试场景尺寸，不是用户真实户型。

包括：

* 右侧大面积落地玻璃窗。
* 窗外原创夜景、远山或星空。
* 靠近窗户的电脑桌与完整桌搭。
* 左后方床、床头柜。
* 中部沙发与地毯。
* 沙发正对的大电视，默认约85英寸视觉比例。
* 靠近入口或休闲区的冰箱。
* 墙面、桌下和机箱灯带。

要求：

* 蓝、白、银灰主色，深色界面配冰蓝强调色。
* 真实合理的家具比例和通道。
* 双屏、笔记本、主机不能互相遮挡或挤在一起。
* 不穿模、不悬空；线材连接合理位置并沿桌面、桌后或理线槽走线。
* 采用米作为3D世界单位，产品毫米尺寸统一换算。
* 默认入口侧斜视角能同时看见电脑桌及主要家具。
* 支持剖切展示或遮挡墙面淡出，避免墙体挡住整个场景。

程序化模型必须具有可辨认结构：椅子有靠背与扶手、键盘有键区、笔记本有屏幕与底座、机箱有内部部件。不能只用几个无细节方块就宣布高质量场景完成。

## 六、核心交互

### 相机

* 左键旋转、滚轮缩放、右键或中键平移。
* 提供操作提示与触控支持。
* 提供默认、房间全景、桌面特写、主机内部四个预设。
* 视角切换平滑，手动操作可中断过渡。
* 限制缩放、俯仰角和目标点范围。
* 提供基础相机碰撞/遮挡处理，避免穿地和钻入主要实体。
* 如仅实现简化包围盒限制，明确说明，不声称具有完整物理碰撞。

### 选择与信息

支持点击机箱、内部硬件、风扇、灯带、两台显示器、笔记本、键鼠、耳机、桌椅、线材、扩展坞、床、电视、沙发、冰箱。

* 通过射线检测选中。
* 选中对象显示清晰描边与信息面板。
* 空白点击取消选择。
* 拖动结束不能误触发点击。
* 两台显示器使用不同实例ID，可以分别选择。
* 列表选择与3D选择双向同步。
* 隐藏或不可见部件不能错误拦截点击。

### 型号与颜色联动

换产品不能只改文字或价格：

* 将所选SKU映射到模型、尺寸、配色和可视特征。
* 没有专属模型时使用参数化示意模型，显示其精度等级。
* 相同外观的SKU允许复用模型，但必须说明。
* 自定义喷涂色与官方在售颜色分开保存和显示，不能把自定义色冒充官方版本。

至少支持桌椅白色/蓝白/黑蓝，机箱白色/银白/黑色，键盘白蓝/纯白/黑蓝，鼠标白色/蓝色/黑色。

### 主机拆装

* 支持侧板显示与隐藏。
* CPU、主板、显卡、两条内存、SSD、电源、水冷和风扇独立选择。
* 提供拆解、组装按钮及0～100%的爆炸视图进度。
* 保存稳定的安装变换，以绝对起终点计算动画，禁止每帧累加导致漂移。
* 重复点击、快速反向切换应安全。
* 动画结束准确回到目标位置。
* 拆解属于结构示意，不冒充真实维修操作指导。

### 灯光和屏幕

* 冰蓝、白色、蓝白缓慢呼吸、关闭。
* 白天与夜间模式。
* 显示器和电视亮度调节。
* 壁纸模式切换。
* 关闭灯效必须真正停止发光和相关动态，不只是按钮变色。
* 尊重减少动态效果设置，禁用呼吸动画及非必要镜头运动。

## 七、数据设计与真实性

至少分离以下实体：

1. Product：品牌、系列、型号、产品类别。
2. SKU：具体配置、官方颜色、尺寸、参数。
3. ProductSource：来源链接、来源类型、核验时间、支持哪些字段。
4. PriceQuote：平台、地区、币种、价格、采集时间、商品链接。
5. ModelAsset：模型地址、授权、比例、坐标轴、精度等级、映射信息。
6. SceneInstance：实例ID、SKU、数量、位置、旋转、自定义颜色。
7. BuildPreset：硬件选择、房间状态、灯光、相机与存储版本。

明确区分：

* 发布日期、营销年份、采集日期。
* 官方颜色、自定义颜色。
* 已核验、部分核验、演示、未知。
* 真实报价、用户预算估值。
* 官方精确模型、第三方模型、参数化示意模型。

未知值使用null或缺失字段，不使用0冒充。

近三年默认采用“当前年份及前两年”，例如2026年为2024—2026年；界面说明此口径。发布日期未知的产品单独列为待核验，不擅自归入年份筛选。

产品来源优先品牌官网、官方商城和官方旗舰店。禁止绕过验证码、访问限制和反爬机制。

## 八、价格与功耗

* 没有可靠价格来源时显示“暂无报价”。
* 用户输入的预算必须标注“预算估值”。
* 不得把自编价格称为参考市场价。
* 主机、外设、家具分别小计，显示总价覆盖率。
* 双屏按两台计价，套装内存不能再乘两次。

功耗规则：

* 主机电源估算只包含由主机PSU供电的组件。
* 显示器、笔记本、电视、冰箱等不计入主机PSU负载。
* CPU TDP不等于实际最大功耗；区分典型、最大及未知。
* 显示估算依据和预留余量，不能把估值包装成实测。
* 不具备可靠输入时输出区间或“信息不足”。

## 九、兼容性规则

至少实现：

1. CPU与主板插槽。
2. 主板CPU支持列表/BIOS要求。
3. DDR代际。
4. 内存容量、条数与插槽。
5. 显卡长度与机箱限长。
6. 显卡厚度与可用空间。
7. 电源额定功率。
8. 显卡供电接口。
9. 360mm冷排安装位及潜在空间冲突。
10. 主板板型与机箱支持。
11. SSD接口、尺寸与可用插槽。
12. 双显示器输出数量和连接方式。
13. 笔记本、扩展坞、线材的视频输出及供电能力。

每条规则返回：

* 规则ID。
* 兼容/警告/不兼容/未知。
* 原因。
* 所依据字段及来源。
* 可行的调整建议。

不因“同为AM5”就保证BIOS支持，不因“USB-C接口”就保证视频输出，不因“DDR5”就保证指定超频频率稳定。

缺少必要数据必须返回未知。整体验证有未知项时不能显示“完全兼容”。

## 十、工作台界面

桌面三栏：

* 左：类别、搜索、品牌/年份/颜色筛选、产品列表、JSON导入入口。
* 中：占主要面积的3D场景、视角、侧板、拆装、灯光和画面控制。

进入页面直接显示场景，不设置阻挡核心操作的宣传首页。

移动端让3D场景优先显示，目录和详情使用抽屉或折叠面板，不横向溢出。

字体要求：常用中文信息至少14px，正文和核心按钮优先16px。状态不能只依赖颜色，图标按钮有aria-label。

## 十一、导入与保存

JSON导入必须包含：

* 文件大小限制。
* Schema验证。
* 类型、单位、枚举及ID重复检查。
* 导入预览。
* 明确的合并/替换策略。
* 错误项说明和取消操作。
* URL协议与字段白名单验证。
* 不执行导入数据中的脚本或HTML。

交付CSV模板及字段说明。CSV导入器不属于必需范围，若未实现应明确说明。

localStorage保存产品、实例颜色、灯光、日夜、亮度、相机预设和保存时间，并包含schemaVersion。

必须处理损坏数据、旧版本、存储不可用和目录产品被删除的情况。保存后刷新能够恢复；恢复完成前不能用默认值覆盖旧方案。

## 十二、性能、加载与异常

* 延迟加载3D渲染模块。
* 共用几何体与材质，合理合批和实例化。
* 只对需要的物体启用阴影。
* 限制像素比，提供低/中/高画质。
* 单一动画循环，后台页面暂停非必要更新。
* 卸载时释放纹理、材质、几何体、监听器和观察器。
* 加载进度必须来自真实阶段或资源状态，不能伪造百分比。
* WebGL不可用、上下文丢失和资源加载失败时提供提示、重试及可用的配置列表。

50～60FPS是性能目标，不是未经测试即可宣布的结果。记录测试设备、浏览器、分辨率、画质和实际测量值。
